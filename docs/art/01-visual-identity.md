| 阶段 | 形态 | 视觉要点 |

| 1 | 杆菌 | 可旋转胶囊 + 横隔 + 2 条鞭毛 |
| 2 | 真核 | 双层膜 + 偏心细胞核 + 4 个细胞器 |
| 3 | 多细胞 | 7 个细胞围成一圈 + 中心团 |
| 4–5 | 组织 / 共生 | 包被 + 5 个内腔 + 中心核团 |

### v3-3 新增的三个符号系统

1. **环形倒计时**：常态海洋阶段 `environment_time_left` 恒为 0，真正走的是
   `event_interval_left`。两者都收在 `ua_environment_timer()` 里判断，UI 只画环。
   环走完 = 这一段时间用完；危机期环色改为红。
2. **升级机能图标**：代谢 = 绕核旋转的细胞器、繁殖 = 正在分裂的两团、
   基因 = 双螺旋。放在升级卡右侧空白，不新增一行文字。
3. **突变纹章**：外环 + 3..7 根辐射触须（数量由 `mutation_id` 决定）+ 中心核，

### v3-4 显微底片层（`tex.c`）

唯一允许的位图。整屏铺一次、颜色由 `tint` 的 RGB 乘算压暗定色相、A 控制强度
（主界面 0.34、全屏页 0.41、展台内 0.25）。规则：

- 必须画在**任何面板之前**，它只能从卡片缝隙和全屏页透出来；
- 永远不覆盖文字，也不参与任何状态表达；
- 文件缺失时静默跳过，界面功能不受影响。

## 0. 怎么用这份文档

三条规则，按顺序执行：

| # | 规则 | 说明 |
|---|---|---|
| R0-1 | **颜色只能来自 token** | 任何 `(Color){ 12, 34, 56, 255 }` 字面量都是 bug。当前 `src/` 下共有 **49 处** 硬编码字面量（screens.c 44 / render.c 4 / ui.c 1），附录 A 给出逐行映射。 |
| R0-2 | **所有度量只能是本文枚举过的值** | 字号 ∈ 6 级阶梯，圆角 ∈ 4 档，描边 ∈ {1, 2}，间距 ∈ 4 的倍数。写了枚举外的值就是 bug。 |
| R0-3 | **约束优先于好看** | 当实现与本文冲突时，改实现；若要改本文，走一次评审并升版本号。 |

本文所有对比度数字都是**实测值**，用以下方法计算（与 WCAG 2.1 一致）：

```
通道线性化： c' = c/255;  c_lin = c' ≤ 0.04045 ? c'/12.92 : ((c'+0.055)/1.055)^2.4
相对亮度：   L = 0.2126·R_lin + 0.7152·G_lin + 0.0722·B_lin
对比度：     CR = (max(L1,L2) + 0.05) / (min(L1,L2) + 0.05)
```

判定门槛引用 WCAG 2.1：**1.4.6（AAA）正文 7:1**、**1.4.3（AA）正文 4.5:1**、**1.4.11 非文本（控件边界）3:1**、**2.3.1 闪烁阈值每秒 ≤ 3 次**。

## 1. 视觉主张与设计支柱

### 1.1 一句话主张

> **暗室培养皿**：每一枚生命都是被冷光照亮的一枚圆形样本，界面是贴在玻片边缘的标签纸。

不是"科幻 HUD"，不是"细胞拟人"，也不是"教科书插图"。是**一个人凌晨三点在显微镜前记录样本时看到的东西**：暗、安静、只有样本本身在发光，其余全是灰绿色的纸与线。

### 1.2 三条设计支柱

| # | 支柱 | 一句话判据 | 违反示例 |
|---|---|---|---|
| P1 | **单光源**：全画面只有一个光源概念——培养皿背光，永远从样本背后透出 | 任何"发光"都必须是同色同心外扩的环或圆，方向恒定 | 给按钮加左上高光条、给卡片加右下投影 → 违反 |
| P2 | **圆是生命，直角是人造** | 生命体只用圆、环、扇形生长；直角、方形、菱形只属于仪器（面板/按钮/图表/进度条） | 用圆角矩形画一个物种头像 → 违反；用圆形做进度条槽 → 违反 |
| P3 | **静态即完整**：任何一帧截图必须自解释，不靠动效传达状态 | 把任意一帧打印出来，玩家仍能判断"什么已解锁、什么能点、什么危险" | 用闪烁表示"可购买"、用呼吸表示"当前物种" → 违反 |

P3 是本文所有取舍的仲裁者。它同时意味着：**动效只做加法，从不做唯一的信号通道**。

## 2. 配色 token

### 2.1 先定基调：**深色**（不做浅色备选）

| 理由 | 说明 |
|---|---|
| R1 题材 | 微生物 / 培养皿 / 暗室显微镜，"暗底 + 透射光"是唯一说得通的光照模型。浅底会把它变成解剖图鉴。 |
| R2 迁移成本 | 现有代码有 **49 处**暗色字面量与 **31 处** `Fade()` 蒙版，全部假设深底。浅色化 = 重画全部叠层，收益为零。 |
| R3 使用场景 | 放置类游戏常驻第二屏 / 长时间挂着。深色显著降低夜间眩光。 |
| R4 中文分级 | 深底上可用"亮度层级"（TEXT/DIM/FAINT）做三层信息分级；浅底上中文字形笔画密度高，层级只能靠灰度差，实测可用层级只剩两层。 |
| 代价与补偿 | 深色在强光环境下对比衰减快 → 用 `COL_LINE` 保持 1.56:1（可感知）与 `COL_LINE_STRONG` 3.92:1（可聚焦）双档补偿；禁止纯黑 `#000000` 大面积铺底。 |

背景/氛围层的设计意图与构图见 `docs/art/02-atmosphere.md`；这里只做**唯一登记处**，保证全工程只有一份色值清单。

**判族方法（重要，避免误判）：** 判断一个颜色属于哪一族，**用「色相 + 相对亮度」，不要用 HSV/HLS 饱和度**。暗色的饱和度会虚高（`COL_VIGNETTE` 的 HLS S=0.47，但它和 `COL_BG` 只差色相 3°）。本工程结构色族的色相窗口为 **186°–193°**，上表三个新色（188/191/193）全部落在窗口内，故均为结构色。

**上面三条由此产生的数量口径**：`16` 个原 token + `9` 个派生 token + `7` 个物种 token + `3` 个氛围 token = **35 个**。其中"新增"的是 `9 + 7 + 3 = 19` 个（任务 #8 的"新增 16 个"是 9+7 的口径，加上氛围层后应为 19）。


### 2.3 三资源必须两两可辨：用「亮度阶梯 + 色相分离」双重编码

| 配对 | 相对亮度差 ΔL | 色相差 Δh | 判定 |
|---|---|---|---|
| ATP ↔ Biomass | 0.092 | 47° | 通过（双通道） |
| ATP ↔ DNA | 0.238 | 187° | 通过（强） |
| Biomass ↔ DNA | 0.165 | 140° | 通过（强） |

设计意图：**三者亮度单调递减** ATP (0.615) > Biomass (0.524) > DNA (0.378)。即使完全去色（灰度打印），三者也仍是三个不同的灰阶——这满足 P3（静态即可读）。

> 色盲注意：ATP 与 Biomass 在红绿色盲（deuteranopia）下都会向黄色偏移，仅靠颜色无法区分。因此**资源色永远是冗余编码**：位置固定（ATP→生物量→DNA→EP 恒为从左到右）、必有文字标签、进度条方向固定。这三条已经在代码里满足，改动时不得破坏。

- 物种色**只做填充与 4px 色轨**，永不做文字色（文字永远 `COL_TEXT`/`COL_DIM`）。
- 物种色饱和度上限 0.55。资源色饱和度区间 0.59–1.00。**"低饱和=身份，高饱和=信号"**——这是本作区分这两族颜色的唯一手段。
- `COL_SP1`（绿）与 `COL_BIOMASS`（绿）色相仅差 6°，靠饱和度 + 形状区分（大圆填充 vs 小数字）。二者**不允许在同一 16px 距离内相邻**。

### 2.5 层级差的最小可见量（防止"分层看不见"）

**先划适用域**：本节只约束**同一画面内、同时可见、直接相邻**的两个不透明面。它**不约束**以下三种情况：

- **跨页 / 跨时间的全屏底色**——两个面从不出现在同一帧里，比较的对象是记忆不是视觉；
- 被半透明遮罩覆盖后的**合成面**（按最终合成色另算，见 §4.4 注③）；
- 已经由描边、色轨、投影**明确划出边界**的面——边界本身就是分隔，面色差只是辅助。

**判据两条，满足其一即达标：**

| 判据 | 形式 | 适用亮度区 |
|---|---|---|
| 对比度 | `CR ≥ 1.10` | 中亮度面（`L ≥ 0.01`） |
| **亮度比** | **`L_hi / L_lo ≥ 1.4`** | **近黑面（`L < 0.01`）** |

**为什么近黑面不能只用 CR：** WCAG 公式里的 `+0.05` 在 `L ≈ 0.005` 时占绝对主导，把差异压扁了。同样"看起来差一档"的两对：

| 对 | CR | 亮度比 `L_hi/L_lo` |
|---|---|---|
| `COL_PANEL` → `COL_PANEL_HI` | **1.136** | **1.69** |
| `COL_BG_DEEP` → `COL_BG` | **1.051** | **1.69** ← 同一个数 |

视觉上是同一档，CR 却差 0.085。**近黑区用 CR 判会把合格判成不合格。**

**而且它不可达：** `CR(COL_BG, 纯黑) = 1.134` —— 这是 `COL_BG` 对**任何**更暗色的理论上限。要在近黑区硬拿 1.10，`COL_BG_DEEP` 得压到 `#030507`（L = 0.0014），那已经不算"更暗的角落"而是纯黑，青色身份和暗角母题会一起失效。**1.10 在近黑区不是严格，是不可达。**

**本工程现役面色的实测（`L` 升序）：**

| 对 | CR | 亮度比 | 判定 |
|---|---|---|---|
| `COL_BG_DEEP`(L=0.0040) ↔ `COL_BG`(L=0.0067) | 1.051 | **1.69** | ✓ **故意如此**——它是"同一空间里更暗的角落"，不是"另一个地方"；两页靠版面与文案区分，不靠底色 |
| `COL_BG` ↔ `COL_PANEL`(L=0.0122) | 1.098 | 1.73 | ✓ 临界，靠 `COL_LINE` 补边界（vs `COL_BG` **1.71** / vs `COL_PANEL` **1.56**） |
| `COL_PANEL` ↔ `COL_PANEL_HI`(L=0.0207) | 1.136 | 1.69 | ✓ |
| `COL_PANEL` ↔ `COL_STAGE`(L=0.0077) | **1.017** | 1.08 | ✗ → 展台**必须**有 `COL_LINE` 描边，不能只靠面色差 |
| `COL_PANEL` ↔ `COL_EP_SURFACE` | 1.02 | — | ✗ → EP 容器**必须**有 `Fade(COL_EP, 0.45)` 描边 |

**后两条不是建议，是这两个组件不能删描边的原因；第 1 条是"这两页不要合并成一个底色、也不要为了凑 1.10 去把深底压成纯黑"的原因。**

### 3.2 最小可读字号：**12 逻辑像素，且 14 才是安全线**

| 事实 | 数值 |
|---|---|
| 中文在 12px 下 | 单字 12×12 像素，横画只剩 1px，"日/目""己/已"开始糊 |
| 中文在 11px 下 | 已不可读，**本文禁止** |
| 逻辑→物理换算 | 物理 px = 逻辑 px × `input_ui_scale()`（1280×800 → 窗口的 letterbox 缩放比） |
| 1920×1080 时 | scale = 1.35 → 12 逻辑 px = 16.2 物理 px ✓ 可读 |
| 4K 时 | scale = 2.70 → 32.4 物理 px ✓ 清晰（依赖 SS 架构，见第 7 节） |
| 960×600（最小窗口）时 | scale = 0.75、SS = 1 → 9 物理 px ✗ 不可读。**该档位排版不保证** |

1. 玩家做决策所必需的文案（按钮、资源名、物种名、效果、代价）**一律 ≥ 14**（`F_BODY` / `F_LABEL`）。
2. 12（`F_CAPTION`）只允许用于**冗余信息**：已在别处出现、或缺失不影响正确操作。
3. 全局下限 **12**，全局上限 **38**（受 7.3-C2 的字号上限 40 约束，只剩 2px 余量）。出现 10/11 一律改 12 或删掉；要做 >38 的 hero，先读 C2。

## 4. 形状语言

### 4.1 圆角：四档，只有四档

| 档 | 逻辑半径 | 用于 | 现实现状 |
|---|---|---|---|
| `R_PANEL` | **16** | 弹层大面板、页面级面板（End of Era 主面板） | 已用 16 ✓ |
| `R_CARD` | **12** | 卡片、物种卡、图鉴格、展台、EP 块 | 已用 12 ✓ |
| `R_BTN` | **10** | 按钮、页签、chip 容器 | 已用 10 ✓ |
| `R_CHIP` | **height / 2** | 胶囊 chip、资源标签、进度条 | 已用 `roundness=0.5` ✓ |

调用方式（保持现有 `ui_panel(r, radius, fill, border)` 签名不变，radius 传上表的值）。禁止出现 8 / 14 / 20 等"手调"圆角。

### 4.2 描边：三档，**必须是整数逻辑像素**

| 档 | 宽度 | 用于 | 备注 |
|---|---|---|---|
| `W_HAIRLINE` | **1** | 容器静态边界、进度条外框 | 唯一允许的最小值 |
| `W_EMPHASIS` | **2** | 可交互焦点、选中项、稀有 chip、当前物种 | 只有"状态"才配用 2 |
| `W_DIVIDER` | **1** | `ui_divider` 内部鱼骨线 | 必须画在 `y + 0.5f`（现有代码已正确），这样 1px 落在像素中心而非跨两像素 |

**为什么必须整数：** 逻辑画布是 1280×800，4K 下整体被放大约 2.7 倍。若描边写成 1.5，它来自 1.5 个纹素 → 上采样后能量摊到 4 个物理像素上，边缘亮度只剩约 38%，看起来是"烟"。写成 0.5 更糟（raylib 会退化为 1px 但坐标半像素偏移，产生亮度不均）。

**对齐靠坐标，不靠宽度。** 需要"贴边"时把矩形 x 取整到 `floorf()`，不要用 0.5 宽度去凑。

> **宽度对了不等于画对了。** 圆角矩形与圆环各有一个"必须换原语"的特例（`DrawRectangleRoundedLinesEx` 在 `thick==1` 时不吃 zoom、`DrawCircleLinesV` 家族恒 1 物理像素），见 **§4.5**。§4.2 和 §4.5 是两道独立的门，都过才算合规。

### 4.3 非文本对比度与"可见的可点击性"（WCAG 1.4.11）

这是当前设计最容易踩的坑，单独说明：

| 场景 | 要求 | 现状 |
|---|---|---|
| `COL_LINE`(1.56) 作为卡片静态边界 | 允许，因为卡片同时有"面色差 + 4px 色轨 + 内容布局"三重冗余 | ✓ |
| 可点击控件在**静止未 hover** 时靠什么证明自己可点？ | 必须有非颜色的线索：`COL_PANEL_HI` 底（1.14）+ 手指光标 + 底部提示 | ✓ 指针已切换 |
| 可点击控件在 **hover / focus** 时 | 边界与相邻色 CR ≥ **3:1** | `COL_ACCENT` 9.31 ✓，`COL_EP` 7.91 ✓ |
| `COL_LINE` 1.56 **不可**单独作为可点击证据 | — | 因此"卡片 = 按钮"的页签容器必须另外有 hover 填充 |

**新增规则：** 任何"整卡即按钮"的组件（升级卡、Legacy 卡、图鉴页签），hover 时必须同时满足：① `COL_PANEL_HOT` 填充 ② `COL_ACCENT` 或 `COL_EP` 2px 描边 ③ 上移 1px。三者缺一，视为状态不可辨。

### 4.4 阴影与发光上限

| 项 | 规则 | 依据 |
|---|---|---|
| 投影（drop shadow） | **禁止** | raylib 无投影 API；用叠色模拟必然出现"右下偏色"，违反 P1（单光源） |
| 发光层数 | **≤ 3 层**同心同色圆/圆角矩形 | 暗底上第 4 层开始混进底噪，边际收益为负 |
| 单层 alpha | **下限：`α × max\|Δchan\| ≥ 3`**（通用算法，见下注①）；**上限：a ≤ 0.10** | 上限：>0.10 会在面板上留下可见的"圆盘边界"。下限：`Δchan` 是该发光色与**它所在底色**的逐通道 8bit 差，`α × max\|Δchan\|` 必须 ≥ 3 才能活过 `round()`。`COL_SP*` 族 `max\|Δchan\| = 153` → α_min = **0.020**（实测 `Fade(COL_SP0, 0.02)` over `COL_STAGE` → `#0D1A1C`，码值差 **(1,3,2)**，G 通道差 3，**刚好踩在阈值上、没有任何余量**） |
| 总 alpha | **≤ 0.18** | 保证发光不会把底下的 `COL_LINE` 洗掉 |
| 发光色 | 必须是**被发光体自身颜色**，不得用白、不得用 `COL_ACCENT` | 白光会让所有生命体变成同一个颜色；`COL_ACCENT` 是"可交互"信号色（§2.2 禁忌②） |

> **注① 下限的通用算法（2026-11-25 起为全项目规则，由 `02-atmosphere.md` §2.6.1 升格）**
>
> **`α_min = 3 / max|Δchan|`**，`Δchan` = 该颜色与它所在底色的逐通道 8bit 差。任何新增的发光、描边、分隔线、图表辅助线、幽灵轮廓，**第一步是算这个值，不是先画出来看**。它把"凭感觉定 α"这个动作消灭了——不必问人、不必截图比对、也不会出现"某分辨率下突然看不见"。
>
> | 颜色 | vs `COL_STAGE` 的 `max\|Δchan\|` | α_min | 说明 |
> |---|---|---|---|
> | `COL_SP0` `#4AB07D` | **153** | **0.020** | **`COL_SP*` 全族统一取此值**（7 个物种色 L 都是 0.340、只变色相，因此各通道 `max\|Δchan\|` 不同；绿通道最敏感，取 `COL_SP0` 的 153 作全族下界即可，**不必逐色列**） |
> | `COL_TEXT` `#ECF4F1` | > 200 | **< 0.015** | 任何 α 都可见 |
> | `COL_LINE` `#2B4145` | **43** | **0.070** | 描边 / 微尘族 |
> | `COL_CELL` `#111E21` | **7** | **0.430** | 面填充专用；α=0.40 只差 2.8 个码值，`round()` 给 3、`floor()`/`lrint()` 给 2 → **时有时无，必须 ≥0.45** |
>
> 这张表把"某个颜色要多少 α"从记忆变成查表。**同一个 α 在不同颜色上可见度差 20 倍**（`COL_SP0` 要 0.02、`COL_CELL` 要 0.43），因为决定可见度的是"色差 × α"，不是 α。
>
> **注② 旧值 0.04 的来历（不要删）**
>
> 0.04 是"还没有公式的年代"取的保守值，它把 `COL_SP*` 族的下限抬高了约 2 倍（公式给 **0.020**）。保留此值于注中，是为了让后来人知道"为什么曾经是 0.04"——否则会有人以为是笔误而随手改掉，再踩一次当年那个坑。
>
> 但 0.04 现在**不是下限，是推荐值**：0.02 是踩着阈值活下来的，任何一个方向的浮点误差都能让它消失；0.04 的 2 倍余量让它在任何舍入模式下都安全。**新写的光晕：先用公式算下限，再决定要不要留 2 倍余量。**

> **注③ 跨色叠加：α 不可加，必须按合成色重算**
>
> 注① 的 `α_min` 与"总 alpha ≤ 0.18"只在**同色多层**（同一发光体的同心层）时可以直接相加。**不同颜色叠在同一条半径上时，α 的可加性不成立**——`Fade()` 逐通道插值，叠加结果与 α 不成线性。
>
> 实测反例（02 §1.2 的母题 A）：两个元素独自叠在 `COL_BG` 上 CR 分别是 **1.039 / 1.135**，叠在一起是 **1.166**，越过了 1.16 的线。
>
> **本工程目前唯一一处"跨色同半径叠加"**：`draw_creature()` 的 `main_line` 环 `DrawRing(c, 1.06R, 1.08R, …, Fade(COL_ACCENT, 0.35f))` 正好落在内层光晕（`1.08R @ 0.08`，物种色）之上。实测：
>
> | 组合 | 合成色 | CR vs `COL_STAGE` | 判定 |
> |---|---|---|---|
> | `Fade(COL_ACCENT, 0.35)` 直接叠 `COL_STAGE` | `#1A5A56` | **2.29** | ✗ 低于非文本 3:1 |
> | 同上，落在 `COL_SP0` 光晕之上（真实情况） | `#1E625B` | **2.56** | ✗ 仍不足 —— 但注意它比裸底**更高**，光晕在这里是帮忙的，不是拖累 |
> | `Fade(COL_ACCENT, 0.50)` 落在光晕之上 | `#237C74` | **3.65** | ✓ |
>
> **结论**：0.35 的环本身够不上 3:1。它至今没在界面上出事，是因为"主谱系"这个信息**同时**由 `card_frame` 的色轨与 `主谱系` 文字标签承担（三重冗余），环只是装饰。**若将来要让它单独承担状态指示，α 必须提到 0.45（叠光晕）/ 0.50（裸底）。**
>
> **⚠ 方向不可假设。** 上面这一例里光晕让环变亮（2.29 → 2.56），**不要因此以为"跨色叠加总是变亮"**。合成色的走向只取决于两个颜色的**相对亮度**：亮色叠在更暗的底上必然变亮；但两个都在暗区、且一处偏青一处偏品红的"发光色叠发光色"，结果可能被**洗向中间**（对比度反而降低）。**每一处跨色叠加都必须单独算合成色，不许套用任何一例的结论。**

现有 `draw_creature()` 用 1.30R@0.06 + 1.12R@0.10 = 2 层 / 总 0.16 ✓ 合规，可直接沿用。

**单层下限带来的一个实际后果：** 加第 3 层时**不能往下压 alpha**（0.06 → 0.02 会直接消失），只能"往外扩半径、保持 ≥ 0.04"（= `COL_SP*` 族公式下限 0.020 的 2 倍余量）。所以 S3 三层的取值是固定的（§5.2 表）：

| S3 层 | 半径 | alpha | 说明 |
|---|---|---|---|
| 内 | `1.08R` | 0.08 | 贴住主体，最亮一层 |
| 中 | `1.24R` | 0.06 | |
| 外 | `1.40R` | 0.04 | 已到**推荐下限**（公式允许 0.02，但那是零余量、浮点一动就消失），**不再下调** |
| 合计 | — | **0.18** | 正好等于总上限，没有再叠第四层的余量 |

### 4.5 圆角矩形与圆的描边：两个"必须换原语"的特例

§4.2 讲的是**宽度取什么值**；这一节讲**哪些原语根本画不对**。两者是独立的两道门，都过才算合规。

#### 4.5.1 圆角矩形描边：方案 A（嵌套填充）

`DrawRectangleRoundedLines[Ex]` 在 `lineThick == 1.0f` 时**不吃 `Camera2D` 的 zoom**（线宽以设备像素计），SS=3 下只有 1 物理像素，且与填充之间多出 1–2px 背景缝。因此 `ui_panel` 的圆角描边一律改成：

1. 外圈整块 `DrawRectangleRounded(r, k_out, 8, border)` —— 铺描边色；
2. 内缩 `W_HAIRLINE` 逻辑 px：`in = { r.x+1, r.y+1, r.width-2, r.height-2 }`；
3. 内圈 `DrawRectangleRounded(in, roundness_of(radius - W_HAIRLINE, in), 8, fill)`。

**内圈 roundness 必须用 `radius − W_HAIRLINE` 与「内缩后」的短边重算，不能复用 `k_out`** —— 复用会让 44 高按钮（radius 10）得到 9.545、216 高的树卡（radius 12）得到 11.888，表现为"角部描边比直边粗"，误差随 `radius/短边` 比值放大。

**唯一例外：半透明填充面**（`fill.a < 255`）。此时内圈填充盖不住外圈描边色（会透出来），只能回退旧路径；回退时把宽度写作 **`1.05f`**（`thickness ∈ (1.0, 1.1666]` 实测在 SS=1/2/3 下恰好给 1/2/3 物理像素；它依赖 raylib 内部 `== 1.0f` 分支，升级会静默失效，故只作止血，推导见 `02-atmosphere.md` 附录 Z.4）并加注释说明。**例外不是许可**：新增半透明面板前先问一句"能不能改成不透明"。

#### 4.5.2 圆与环：`DrawRing(R − 0.5f, R + 0.5f)`，**且不得随 SS 分档**

凡"1 逻辑 px 的圆环"（培养皿环、点击涟漪、选中环、光晕边），一律：

```c
DrawRing(c, R - 0.5f, R + 0.5f, 0.0f, 360.0f, 64, color);
```

禁用 `DrawCircleLines` / `DrawCircleLinesV` / `DrawRingLines` / `DrawCircleSectorLines`（Z-UNSAFE，机制见 `02-atmosphere.md` 附录 Z）。

**项目铁律（主理人 2026-11-25 裁定）：半宽恒为 `0.5f`，任何绘制调用里都不许出现 `ss` 分支（`if (ss == 2)` / `(ss <= 1) ? a : b` 一律禁止）。**

理由不止是"环宽会变"——**一旦绘制里出现 `ss` 分支，C1（绘制可翻译成纯覆盖赋值）就永久失效**：以后没人能靠读代码验算 SS=1 与 SS=3 是否一致，只能靠跑两遍截图对比。这条约束比 `R±0.5f` 本身重要得多，它保护的是**可验算性**。

实测依据（SS=1/2/3 × R∈{18,26,44,60} × 圆心取整数/半像素偏移，共 36 组，每环采 1440 个角度）：

| 项 | `±0.5f` | `±0.75f` |
|---|---|---|
| 断成虚线的角度数（36 组总计） | **0 / 51840** | **0 / 51840** |
| 环宽实测（逻辑 px，SS=1/2/3 均值） | 1.00 / 1.00 / 1.00 | 1.50 / 1.53 / 1.50 |
| SS=1 的宽度波动 Δ | 0.39 – 1.13 | 0.46 – 0.93（**没有更稳**） |

三条结论：

1. **`±0.5f` 在任何 SS、任何半径、任何亚像素圆心下都不会断。** `DrawRing` 是**填充**环（三角扇），不是 GL 线段，根本没有"1px 发丝被浮点误差打断"这种失效模式——那个坑属于 `DrawCircleLinesV`，不属于 `DrawRing`。**别把 A 原语的病算到 B 原语头上。**
2. **`±0.75f` 换不到任何稳定性**，只把环宽从 1.0 提到 1.5（面积 +50%），而 1.5 **违反 §4.2「描边必须是整数逻辑像素」**。
3. **按 SS 分档会直接违反 §7.3 的 C1**：SS=1 的窗口就不再是 4K 的忠实预览，而"SS=1 与 SS=3 视觉一致"是这套超采样架构唯一的正确性凭据。**唯一的 SS 分支必须留在 `ui_canvas_ss()` 里，任何绘制调用里都不许出现。**

> SS=1 时那 ±25% 的宽度波动是 **1 设备像素光栅化的物理下限**，任何 1px 圆形描边都有；它不是 `DrawRing` 的缺陷，也不是 0.75 能修掉的东西。**接受它，别修它。**

### 4.6 进化树亲缘连线（D1 已清）

**布局先于连线**：卡片按 `ua_species_stage()` 分列，不按 `species_id` 摆网格。
ID 顺序的阶段分布是 `0,1,1,2 / 2,3,3`，按 ID 连线会交叉成网；按阶段分列后亲本恒在左侧，只剩分叉、没有回边。
列数由最大阶段动态求出，列间距 56 逻辑像素，卡片在列内垂直居中。

**连线几何**：三段 90° 折线，竖直段落在两列之间的空隙里，不进卡片、不压文字。
锚点取卡片内生命圆的左右边缘，线在卡片下层绘制；不透明卡片会盖住跨阶段连线穿过中间列的那一小段
（如阶段 1 → 阶段 3），读起来是"从节点背后绕过去"，这是预期效果，不是断线。

**数据所有权**：亲本来自只读查询 `ua_species_parents(species_id, out, max_out)`（见 `ui_adapter.h` / 提案 P1-10），
由 B 的分化表实现。UI 不自己推断亲缘，也不拿它参与任何规则判定——它只是画线的坐标来源。

**三级语义，只靠颜色、不靠粗细**（A4 要求描边宽度 ∈ {1,2}）：

| 语义 | 颜色 | 宽度 |
|---|---|---|
| 当前物种的入边 | `Fade(COL_ACCENT, 0.92)` | 2 逻辑 px |
| 两端都已发现的其他分支 | `Fade(ecology_color(child), 0.72)` | 2 逻辑 px |
| 任一端未发现 | `Fade(COL_LINE_STRONG, 0.34)` | 2 逻辑 px |

**原语**：只用 `DrawLineEx` 与 `DrawCircleV`（三角形填充路径），线宽与端点圆半径都跟随 `Camera2D.zoom`；
禁用 `DrawCircleLines` / `DrawRectangleRoundedLinesEx` 等设备像素原语（Z-UNSAFE，见 Z-A1）。
4K 实测：2 逻辑 px → 6 物理像素，端点圆半径 3 → 9 物理像素，折角与卡片边缘衔接无断缝。

### 5.2 生物形态：一个恒等式 + 四套阶段模板

**恒等式（本作最重要的实现约束）：**

> 所有形态元素尺寸都写成 `R × 系数`，`R` 由调用方给（主展台 96 / 双物种时 74 与 58 / 图鉴头像 22 / 进化树节点 26）。
> 于是**同一个模板在 22px 和 96px 下都成立**——这是 UI 与图鉴共享"同一只生物"的唯一办法。

**关于物种数量：** 代码里是 **7 个物种（`SPECIES_COUNT`）、4 个阶段（0–3）**。因此形态按**阶段**分 4 套模板，物种差异 = 身份色（2.4 节）+ 1 个特征装饰。不要为 7 个物种各画一套，那是 7 份维护成本换 0 收益。

#### 阶段模板表

| 元素 | S0 单细胞 | S1 功能化 | S2 群体 | S3 器官化 |
|---|---|---|---|---|
| 代表物种 | 原始细胞 | 光合细菌 / 化能细菌 | 藻类真核 / 原生动物 | 多细胞群体 / 极端环境群体 |
| 光晕层 | 1 层 | 2 层 | 2 层 | 3 层 |
| 主体 | 1 圆 `1.00R` | 1 圆 `1.00R` | 1 圆 `0.86R` | 1 圆 `0.90R` |
| 附属圆 | 无 | 2 伪足 `0.30R` @ `0.72R` | 4 卫星 `0.22R` @ `1.00R` | 无卫星，改双环 |
| 轮廓环 | 无 | `DrawRing 0.97R→1.02R` @0.30 | 无（卫星自带轮廓） | `0.97R→1.01R` @0.32 + `1.05R→1.07R` @0.18 |
| 分区 | 无 | 无 | 无 | 3× `DrawCircleSector(0.86R, a₀, 55°, 24)` @0.10，a₀=0/120/240 |

| 细胞器 | 0 | 3 @ `0.55R`, r=`0.06R` | 5 @ `0.50–0.70R`, r=`0.055R` | 7 @ `0.35–0.75R`, r=`0.05R` |
| 呼吸振幅 | ±3% | ±2% | ±1.2% | ±0.6% |
| 绘制调用 | **5** | **12** | **15** | **18** |

#### 递进律（这是本作的核心视觉叙事，必须逐条可测）

| 律 | 从 → 到 | 读作 |
|---|---|---|
| L1 | 核半径 `0.34R → 0.20R` 单调递减 | 个体变小 |
| L2 | 结构化元素数 `0 → 5` 单调递增（伪足 2 → 卫星 4 → 环 2 + 扇区 3） | 系统变大 |
| L3 | 绘制调用 `5 → 12 → 15 → 18` 单调递增（也是性能预算表；附录 C.2 有逐阶段计数） | 复杂度上升 |
| L4 | 呼吸振幅 `3% → 0.6%` 单调递减 | 越高级越稳（低等生物"飘"，高等生物"定"） |
| L5 | 核移动性 `漂移↑ → 0` | 从"散装"到"有中心" |

L1 + L2 是同一句话的两面：**"细胞核在缩小，世界在变大"**。这两条一旦被破坏（比如给 S0 画一圈卫星），进化感立刻消失，玩家会认为"只是换了个颜色"。

#### 每个物种的 1 个特征装饰（优先级从高到低实施）

| 物种 | 装饰 | 实现 |
|---|---|---|
| 光合细菌 | 2 个叶绿点 | 2× `DrawCircleV(c + (±0.45R, 0.35R), 0.09R)` @0.50，用 `COL_SP1` 提亮 1 档 |

| 原生动物 | 2 个吞噬泡 | 2× `DrawRing`，半径 `0.18R`，线宽 1.5px，绕 `0.70R` 轨道，角度 `t·0.4 + iπ` |

### 5.3 展台背景（`draw_stage` 内那 8 行气泡）的替换规格

`screens.c` 当前这段（约 319–326 行）有两个问题，**逐条对应本文的既有规则**：

| 问题 | 违反 |
|---|---|
| `y` 随 `S->time` 匀速上浮并 `fmodf` 回绕 | §8.3「禁止无限平移循环」——循环只允许 scale / alpha / 半径 / 角度 |
| 颜色用 `Fade(COL_ACCENT, 0.10f)` | §2.2 禁忌②「`COL_ACCENT` 不可用于背景/装饰」；在背景层它读作"发光"，而不是"培养液里的悬浮物" |

**替换规格（18 → 6 个调用，位置固定，只做 alpha 呼吸）：**

```c
/* 展台介质微尘：6 个固定位置，不位移，只做 alpha 呼吸（周期 3.1s） */
for (int i = 0; i < 6; ++i) {
    float seed = (float)i * 12.9898f;
    float x = r.x + 30.0f + fmodf(seed * 37.0f, r.width  - 60.0f);
    float y = r.y + 40.0f + fmodf(seed * 53.0f, r.height - 80.0f);   /* 固定，不随时间回绕 */
    float br = 0.5f + 0.5f * sinf(S->time * (2.0f * PI / 3.1f) + (float)i * 1.1f);
    float a  = 0.10f + 0.06f * br;                                   /* 0.10 .. 0.16 */
    float rr = 1.2f + fmodf(seed, 2.0f) * 0.3f;                      /* 1.2 .. 1.8 */
    DrawCircleV((Vector2){ x, y }, rr, Fade(COL_LINE, a));
}
```

**为什么是 `Fade(COL_LINE, ·)` 而不是 `Fade(COL_CELL, ·)`：** 实测 `COL_CELL`(#111E21) 在 α=0.04–0.09 下叠到 `COL_STAGE`(#0C171A) 只产生 **0.3–0.6 个 8bit 码值**的差（`#0C171A` → `#0C181B`），四舍五入后**等于没画**。`COL_LINE`(#2B4145) 在 α0.10 时有 3–4 个码值、α0.16 时有 5–7 个码值，是"存在但退到后面"的正确量级。且不新增 token：微尘的浓度刻意等于描边同级，只是被 α 压到 1/6。

`COL_CELL` 的大面积细胞不受此影响——大面积需要 α ≈ 0.45–0.60 才起色（公式下限 0.43，见 §2.2b 与 §4.4 注①）。

**绘制顺序（硬规则，不许改）：** 展台背景 → `draw_creature()`。生命体圆心 `R × 1.35` 范围内是母题禁区，背景元素不得进入；背景永远先画，生命体后画。一旦顺序反过来，背景会盖在生命体上，这是全工程唯一会产生"背景抢戏"的路径。

**归属：** 这 8 行归 ③（`draw_stage` / `draw_creature` 重构）。**不要由背景层任务单独改这 8 行**，两处都改会产生冲突。

## 7. 4K / 高 DPI 可读性

### 7.1 现状：4K 发虚问题已由超采样（SS）解决，本节改为"别把它弄坏"

写本文时工程已把渲染路径改成超采样（`ui.c` / `render.c` / `main.c`）：

```
SS   = clamp(ceil(min(winW/1280, winH/800)), 1, 3)     // compute_ss()
画布 = LoadRenderTexture(UI_W*SS, UI_H*SS)             // canvas_ensure()
绘制: BeginMode2D(camera with zoom = SS)               // 逻辑 1280×800 → 画布像素 x*SS
字体: LoadFontEx(..., UI_FONT_BASE_SIZE = 120, ...)    // 图集按 120px 光栅化
输出: DrawTexturePro(整张 SS 画布 → letterbox dst)      // 可能是下采样
```

这套架构下，**逻辑像素不再等于纹素**，1 逻辑像素 = SS 个纹素，字形从 120px 图集降采样命中。结论完全变了：

| 窗口 | scale | SS | 画布 | 12px 字的实际物理高度 | 判定 |
|---|---|---|---|---|---|
| 960×600（最小窗口） | 0.75 | 1 | 1280×800 | 9 px，缩 10 倍 | **不保证排版**（实测可读但偏细） |
| 1280×800 | 1.00 | 1 | 1280×800 | 12 px，缩 10 倍 → 笔画偏细，字形不崩 | 底线 |
| 1600×1000 | 1.25 | 2 | 2560×1600 | 15 px，缩 5 倍 | **设计目标** |
| 1920×1080 | 1.35 | 2 | 2560×1600 | 16.2 px，最后 0.675 下采样 | 清晰 |
| 3840×2160 | 2.70 | 3 | 3840×2400 | 32.4 px，最后 0.9 下采样 | 清晰 |

因此：**4K 清晰度不是本节要解决的问题了**。本节只定义"用了 SS 之后美术侧必须守的纪律"，否则这套超采样会被画法抵消掉。

> 上表已实测：`./treeoflife.exe --shot --ss 3` 出 3840×2400 图，裁 1:1 区域检视，12 逻辑 px 的中文与拉丁字形边缘锐利、无插值灰边；`--ss 1 --w 960 --h 600` 出 1280×800 图，同区域字形正确但笔画偏细。两条命令都可复现，本文档任何配色/字号改动都可以用它做回归。

### 7.2 编号规则

| # | 规则 | 原因 |
|---|---|---|
| R1 | 描边宽度只能是**整数逻辑像素**（1 或 2）；禁止 0.5 / 1.5 / 任意非整数 | SS 会把逻辑像素放大 2–3 倍。2.5 个纹素经过最后的非整数倍下采样，会让**同一条线一段粗一段细**。整数是唯一能保证"粗细均匀"的写法 |
| R2 | 最细分割线 **1 逻辑像素**，画在 `y + 0.5f`，且与相邻面色 CR ≥ 1.5 | `COL_LINE` 1.56 达标。现在线实际有 2–3 纹素宽，比 1280 时代结实得多，所以下限仍是 1 而不是 2 |
| R3 | 文字与任意描边的**间距 ≥ 12 逻辑像素**（绝对下限 4） | 描边锐化了，但 12px 字 + 1px 框在 4K 上仍显"紧"。12 是排版呼吸，不是防糊 |
| R4 | 最小字号 **12**；承载决策的文字 **≥ 14** | 见 3.2 |
| R5 | 纯色大面积：允许，但单块纯色 **≤ 520×300**，超过必须叠一层 `COL_STAGE` 或 `COL_SURFACE_OFF` inset（CR 1.06–1.08） | 最后的非整数倍下采样会在纯色面上留下极淡的渐变台阶（banding），面积越大越明显 |
| R6 | 渐变：raylib 5.5 **有** `DrawRectangleGradientV/H/Ex`，但**仅轴对齐矩形**。圆角形状禁用渐变（矩形会直角裁掉圆角）。圆角处需渐隐时用同心叠层，**最多 3 层，相邻 alpha 步进 ≤ 0.04** | 暗底上步进 > 0.04 就能看出环与环的接缝 |
| R7 | 任何"状态"都不许只靠 1 逻辑像素表达（焦点框、下划线、选中条）。状态线最低 2 | 1px 的 `COL_ACCENT` 在 32px 高的卡片旁不构成"醒目"，与 4.3 的 3:1 要求是两件事 |

### 7.3 与超采样架构的三条耦合约束

这三条是本文与 `ui.c` 实现之间的**契约**，违反任意一条都会让 SS 白做。

| # | 约束 | 后果 |
|---|---|---|
| C1 | **逻辑坐标纪律**：新绘制一律在 1280×800 坐标系里画。禁止手动乘 SS，禁止调用 `ui_canvas_ss()` 参与任何尺寸计算。**更好的判据写法：SS 只允许存在于 `ui_canvas_ss()` 一个函数里；任何绘制调用里出现 `ss` 分支（`if (ss == 2)` / `(ss <= 1) ? a : b`）即判定违约** | 一旦有代码乘 SS，那部分就会比周围大一倍，且窗口 resize 时错位。**"少读 SS"是态度，"SS 只在一个函数里存在"是可验算的判据** —— 前者靠自觉，后者 grep 就能查 |
| C2 | **字号上限 = `UI_FONT_BASE_SIZE / SS_max` = 120 / 3 = 40**。当前阶梯最高 38，**余量仅 2px** | 任何人想加 44 的 hero 字号，字形就会超出图集原始分辨率、被插值放大 → 反而比 38 糊。加之前必须同时把 `UI_FONT_BASE_SIZE` 提到 160（图集 21MB → 37MB）。这条写在此处就是为了防止"改个字号"这种看似无害的改动把 4K 清晰度打回去 |
| C3 | **最小保证窗口 = 1600×1000（SS ≥ 2）**。960×600（`SetWindowMinSize`）只保证"可运行"，不保证排版 | SS=1 时 `F_CAPTION`(12) 是从 120px 图集单次双线性缩小 10 倍绘制的。实测（`--shot --ss 1 --w 960 --h 600`）：**字形不崩、仍可辨认**，但笔画比 SS=3 细一档、灰度对比降一档。所以这一档不是"坏"，是"不达展示标准"——而 12 本来就只允许用于冗余信息，故视为可接受；不建议把 12 提升到 14（会撑破顶栏 pill 的 56px 高） |

## 8. 动效原则

### 8.1 总则

1. **动效只做加法**（P3）：任何状态都必须静态可读，动效只是让它更顺。
2. **界面过渡 ≤ 300ms**。生命体自身的循环动画不受此限。
3. **缓动只允许 4 条曲线**：`ease-out-cubic`（进场）、`ease-in-quad`（退场）、`ease-out-quad`（位移/涟漪）、`ease-out-back(c1=1.10，过冲 ≈5.5%)`（生长回弹）。禁止 linear（进度条趋近除外）、禁止 elastic、禁止 bounce。

```c
static float ease_out_cubic(float u){ float v = 1.0f - u; return 1.0f - v*v*v; }
static float ease_in_quad (float u){ return u*u; }
static float ease_out_quad (float u){ return 1.0f - (1.0f-u)*(1.0f-u); }
static float ease_out_back (float u){ const float c1 = 1.10f, c3 = c1 + 1.0f;
                                      float v = u - 1.0f; return 1.0f + c3*v*v*v + c1*v*v; }
```

### 8.2 允许清单

| 动效 | 用途 | 时长 | 缓动 | 幅度 | 循环 |
|---|---|---|---|---|---|
| 呼吸 | 生命体待机 | 3.9s | `sin` | 半径 ±3%（S0）→ ±0.6%（S3） | 无限 |
| 漂浮 | 核 / 细胞器 / 伪足 | 6–10s（两轴不同相位） | `sin` | 位移 ≤ `0.14R` | 无限 |
| hover 抬升 | 卡片 / 按钮 | 120ms | ease-out-cubic | 上移 1 逻辑 px + 2px 强调描边 | 单次 |
| 按下回弹 | 主按钮 | 下 80ms / 上 120ms | ease-out | 缩放 1.00→0.98→1.00 | 单次 |
| 数字滚动 | 资源数值变化 | 300ms | ease-out-cubic | 旧值→新值插值 | 单次 |
| 生长 | 阶段跃迁 | 640ms | 0–40% ease-in 缩到 0.92；40–100% ease-out-back 回 1.00 | 缩放 | 单次 |
| 点击涟漪 | 点击生命体 | 420ms | ease-out-quad | 环 `r: 0.60R→1.08R`，alpha `0.45→0` | 单次 |
| 弹层进场 | 遮罩 + 面板 | 180ms | ease-out-cubic | 遮罩 alpha `0→0.72`；面板 `y+8→0`，scale `0.98→1.00` | 单次 |
| 弹层退场 | 同上 | 140ms | ease-in-quad | 反向 | 单次 |
| toast | 提示条 | 进 160ms / 停 2.0s / 退 140ms | ease-out-cubic | `y+8→0`，alpha `0→1` | 单次 |
| 进度条填充 | 所有 bar | 180ms 到 90% | 指数趋近 | — | 连续 |

### 8.3 禁止清单

| 禁止 | 原因 |
|---|---|
| **闪烁**：任何区域的亮度变化 > 2 次/秒 | WCAG 2.3.1（3 次/秒阈值）留一倍安全余量；且违反 P1/P3 |
| **抖动 / 震屏**：面板级或全屏位移 | 破坏"玻片是静止的"这一物理隐喻 |
| **界面过渡 > 300ms** | 放置游戏点按频率高，长过渡会把操作变成等待 |
| **无限平移循环**：整体 x/y 位移循环 | 阅读中的文字会"游走"，可访问性事故。循环只允许 scale / alpha / 半径 / 角度 |
| **用动效单独承载状态**（只在 hover 时显示代价、只在脉冲时显示"可购买"） | 违反 P3 |
| **过冲 > 8%** 的弹性 | ease-out-back 的 c1 上限 1.10 |

### 8.4 三个可直接抄的参数示例

**例 1｜呼吸（按阶段取振幅）**
```c
static const float AMP[4] = { 0.030f, 0.020f, 0.012f, 0.006f };  /* S0..S3 */
static const float PERIOD  = 3.9f;                                /* 秒 */
float phase = g_ui.time * (2.0f * PI / PERIOD);
float k = 1.0f + AMP[stage] * sinf(phase);
DrawCircleV(c, R * k, body);
```

**例 2｜hover 抬升（120ms，插值而非瞬移）**
```c
/* 目标 0/1，指数趋近等价于 ease-out-cubic 观感，且无需记起始时间 */
b->hover += (target - b->hover) * fminf(1.0f, dt / 0.12f);
float dy = -1.0f * ease_out_cubic(b->hover);      /* 0 → -1.0 逻辑像素 */
Rectangle r = b->rect; r.y += dy;
ui_panel(r, R_BTN, fill, b->hover > 0.02f ? COL_ACCENT : COL_LINE);
```
> 现有 `ui_btn_draw` 是 `if (hot) r.y -= 1.0f;`（瞬移）。改为上式即可，成本 3 行。需要在 `UiButton` 加一个 `float hover;` 字段。

**例 3｜生长动画（640ms，两段）**
```c
/* u: 0..1，跃迁触发后累加 dt/0.64 */
float s;
if (u < 0.40f) { float v = u / 0.40f;      s = 1.0f - 0.08f * ease_in_quad(v); }
else           { float v = (u-0.40f)/0.60f; s = 0.92f + 0.08f * ease_out_back(v); }
DrawCircleV(c, R * s, body);   /* 0.92 → 1.00，过冲约 1.004 */
```

### C.2 `draw_creature()` 四套阶段模板（可直接翻译）

签名保持现有 `draw_creature(float cx, float cy, float R, int species_id, float t, bool main_line)`，`stage = ua_species_stage(species_id)`。所有尺寸都是 `R` 的倍数——**这是 22px 头像与 96px 展台共用同一套模板的唯一前提**。

```c
/* 通用：呼吸振幅按阶段递减（§5.2 L4） */
static const float AMP[4] = { 0.030f, 0.020f, 0.012f, 0.006f };
float breathe = 1.0f + AMP[stage] * sinf(t * (2.0f * PI / 3.9f));

Color base = ecology_color(species_id);

/* ── 1. 光晕：外→内，层数 1/2/2/3，单层 0.04..0.10，总 ≤0.18 ── */
if (stage == 0) {
    DrawCircleV(c, R * 1.22f, Fade(base, 0.06f));                                  /* 总 0.06 */
} else if (stage == 1) {
    DrawCircleV(c, R * 1.26f, Fade(base, 0.05f));
    DrawCircleV(c, R * 1.12f, Fade(base, 0.07f));                                  /* 总 0.12 */
} else if (stage == 2) {
    DrawCircleV(c, R * 1.24f, Fade(base, 0.05f));
    DrawCircleV(c, R * 1.10f, Fade(base, 0.07f));                                  /* 总 0.12 */
} else {
    DrawCircleV(c, R * 1.40f, Fade(base, 0.04f));   /* 最外层，已到可见下限，不可再暗 */
    DrawCircleV(c, R * 1.24f, Fade(base, 0.06f));
    DrawCircleV(c, R * 1.08f, Fade(base, 0.08f));                                  /* 总 0.18 = 上限 */
}

/* ── 2. 附属结构（画在主体之下，形成轮廓） ── */
if (stage == 1) {
    for (int i = 0; i < 2; ++i) {                       /* 2 条伪足 */
        float a = t * 0.15f + (float)i * PI;
        DrawCircleV((Vector2){ cx + cosf(a) * R * 0.72f, cy + sinf(a) * R * 0.72f },
                    R * 0.30f, Fade(base, 0.55f));
    }
} else if (stage == 2) {
    for (int i = 0; i < 4; ++i) {                       /* 4 个卫星圆 */
        float a = t * 0.18f + (float)i * (PI * 0.5f);
        DrawCircleV((Vector2){ cx + cosf(a) * R * 1.00f, cy + sinf(a) * R * 1.00f },
                    R * 0.22f, Fade(base, 0.80f));
    }
} else if (stage == 3) {
    for (int i = 0; i < 3; ++i) {                       /* 3 个组织分区扇形 */
        DrawCircleSector(c, R * 0.86f, 120.0f * (float)i, 120.0f * (float)i + 55.0f,
                         24, Fade(base, 0.10f));
    }
}

/* ── 3. 主体 + 内膜 ── */
float bodyR = (stage == 0 || stage == 1) ? R : (stage == 2 ? R * 0.86f : R * 0.90f);
DrawCircleV(c, bodyR * breathe, base);
DrawCircleV(c, bodyR * 0.94f, Fade(COL_TEXT, 0.06f));

/* ── 4. 轮廓环（S1 单环 / S3 双环，S0 S2 无） ── */
if (stage == 1) {
    DrawRing(c, bodyR * 0.97f, bodyR * 1.02f, 0, 360, 72, Fade(base, 0.30f));
} else if (stage == 3) {
    DrawRing(c, bodyR * 0.97f, bodyR * 1.01f, 0, 360, 72, Fade(base, 0.32f));
    DrawRing(c, bodyR * 1.05f, bodyR * 1.07f, 0, 360, 72, Fade(base, 0.18f));
}

/* ── 5. 核：半径单调递减 0.34→0.30→0.24→0.20，漂移 0→0.10→0.14→0 ── */
static const float NUC_R[4]   = { 0.34f, 0.30f, 0.24f, 0.20f };
static const float NUC_DRIFT[4] = { 0.0f, 0.10f, 0.14f, 0.0f };  /* S3 = 0：器官化即中心化 */
float nx = cx + cosf(t * 0.60f) * R * NUC_DRIFT[stage];
float ny = cy + sinf(t * 0.50f) * R * NUC_DRIFT[stage];
DrawCircleV((Vector2){ nx, ny }, R * NUC_R[stage],        Fade(COL_BG_DEEP, 0.55f));
DrawCircleV((Vector2){ nx, ny }, R * NUC_R[stage] * 0.70f, Fade(COL_TEXT, 0.28f));

/* ── 6. 细胞器：0 / 3 / 5 / 7 个 ── */
static const int   ORG_N[4]     = { 0, 3, 5, 7 };
static const float ORG_R[4]     = { 0.0f, 0.060f, 0.055f, 0.050f };
for (int i = 0; i < ORG_N[stage]; ++i) {
    float a  = t * 0.70f + (float)i * 1.25f;
    float rr = R * (0.50f + 0.10f * (float)(i % 3));   /* 0.50..0.70，S3 可放宽到 0.35..0.75 */
    DrawCircleV((Vector2){ cx + cosf(a) * rr, cy + sinf(a) * rr },
                R * ORG_R[stage] + 0.5f, Fade(COL_TEXT, 0.55f));
}

/* ── 7. 主谱系标记（唯一用 COL_ACCENT 的地方，符合 §2.2 禁忌②） ── */
if (main_line) DrawRing(c, R * 1.06f, R * 1.08f, 0, 360, 72, Fade(COL_ACCENT, 0.35f));
```

### v4c · 反馈层：采集浮字 + 提示条搬进底栏

线上发现的两个问题，都是"反馈层和内容层抢同一处像素"：

1. **提示条压在"下一步"页脚上。** `draw_toast()` 原位置 `y = 686`、文字画在 697，
   而"下一步"面板的页脚在 `554 + 142 = 696` —— 同一行。截图里就是两行字互相穿过去。
   主界面从 100 到 736 没有一条空着的横带，唯一不压文字的地方是**底栏按钮右侧**
   （584 → 1260）。所以提示条改为底栏右段：`y = 744`、`h = H_PRIMARY = 44`，
   右对齐 1260 往左长（短提示贴右锚点，长串退 F_CAPTION，上限 624）。
   提示条在场时，底栏右下的常驻快捷键提示让位 —— 同一条基线上只放一条信息。

2. **采集反馈不该走提示条。** 空格连点时每秒能触发好几次，提示条就成了闪烁的数字灯，
   还会跟第 1 条里的页脚打架。现在采集只做两件事：
   - `g_ui.gain_t[3] / gain_val[3]` 三槽轮换，每槽 0.7s 独立上飘 26px + 淡出；
     单槽会被下一次点击重置成 1.0 而原地闪，三槽之后连点就是连续冒泡。
   - `g_ui.flash` 皿圈闪光（原有）。
   浮字纵向落在 `c.y−2 → c.y−28`：再上层是 `+x / 次`（收在 `c.y−38`），
   下层是活体上沿（`c.y−8`），46px 的空档里只能二选一 —— 让浮字压图形。

提示条、导出的 PNG 里永远没有"；现在截图流程与 `ui_render()` 逐层一致

### 星图进化树：只拉开间距

保留极坐标星图（一圈一个阶段），三处改动解决拥挤：

1. **圆 → 略扁的椭圆**：`rx = 1.75·ry`。旧版是 2.3 倍，左右拉得过开、上下挤成一团。
2. **角度按叶子等分**：每个叶支固定 2π/叶数，兄弟节点各占一份配额，不会再共享一条半径。
3. **每往外一圈整体拧 0.085 rad**：父子不再同角度 —— 这既让连线呈螺旋，也让标签
   不再沿半径叠罗汉（这是旧版"名字叠成一团"的真正原因）。
4. 内圈半径抬到 58（原来 26）：阶段 1–3 的节点从圆心附近搬开。

标签沿用"外 / 内 / 上下 45° / 正后方 × 两档距离"的八候选避让，避让矩形外扩 3px；
挤不下的普通名字直接不画，当前/选中/路线上的一定画。圈号不再写文字（11 个"阶段 N"
会在轴上叠成一串），只留刻度点，阶段数在底部详情条里跟着选中物种显示。
