# Tree of Life · 数据与计算规则

## 1. 文档用途

本文件补全项目进入编码前缺少的精确规则。三个成员及其 Agent 必须使用这里的编号、公式、初始值和计算顺序。试玩后允许集中调整常量，不允许在不同模块中各写一套公式。

第一版平衡目标如下。

- 第一次分化约在开局 2 至 4 分钟出现。
- 第一轮获得有意义的 EP 约需 8 至 12 分钟。
- 有永久强化后的常规轮次约为 5 至 8 分钟。
- 课堂展示可使用预先准备的存档，不为缩短演示而改变正式规则。

上述时间是验收目标。若试玩不符合，只调整本文件中的价格、产率和时间常量。

## 2. 固定步长与计算顺序

核心模拟使用 `0.1` 秒固定步长。每个固定步严格按以下顺序执行。

1. 读取步开始时的 `GameState`，不立即修改。
2. B 为每个活跃物种计算 `SpeciesRates`。
3. A 汇总所有物种的 ATP、Biomass、DNA 和种群变化。
4. A 同时写回所有物种的新种群，避免数组顺序影响结果。
5. A 更新三种资源和本轮最高 Biomass。
6. B 根据写回后的临时状态计算 `EnvironmentStep`。
7. A 写回环境计时、事件切换和危机统计。
8. A 检查 Biomass 里程碑、物种发现和突变发现。

页面暂停、End of Era 预览和 Legacy 阶段不执行模拟步。

## 4. 单轮升级

### 4.1 价格

第 `level` 次购买前，价格按当前等级计算。

```text
Metabolism ATP cost   = floor(20 × 1.25^level)
Reproduction ATP cost = floor(35 × 1.30^level)
Genome Biomass cost   = floor(25 × 1.30^level)
```

三项单轮升级不再有硬顶，收益线性累加（+25% / +20% / +25% 每级），价格继续按上式的指数增长。

### 4.2 效果

```text
Metabolism multiplier   = 1 + 0.25 × metabolism_level
Reproduction multiplier = 1 + 0.20 × reproduction_level
Genome multiplier       = 1 + 0.25 × genome_level
```

Metabolism 同时提高自动 ATP 和点击 ATP。Reproduction 提高正向种群增长与 Biomass 产出。Genome 提高 DNA 产出。

点击收益为：

```text
click_ATP = BASE_CLICK_ATP
          × Metabolism multiplier
          × permanent ATP multiplier
```

### 5.5 分化后的种群

- 没有第二物种槽时，后代成为新的主谱系，获得亲本当前种群的 `70%`，最低为 10。亲本离开活跃列表，但保留图鉴记录。
- 已有第二物种槽且选择保留亲本时，后代获得原种群的 `60%`，亲本保留 `40%`。
- 第二物种槽已经被占用时，玩家选择保留旧额外分支，或用本次亲本替换旧额外分支。
- 额外物种槽本身也可以分化：后代原地替换该槽，继承该槽物种的突变，主谱系保持不变；保留亲本选项仍只用于主谱系分化。
- `Diversification Lv.5` 把活跃物种槽从 2 个扩展到 3 个；保留亲本时优先占空槽，槽满时替换一个非主谱系的额外分支。
- 后代继承亲本已有突变。亲本与后代之后分别保存自己的新突变。
- `Diversification Lv.4` 使表中 Biomass 分化成本乘以 `0.85`。

### 6.3 突变成本折扣

```text
Mutation Lv.0 = 0%
Mutation Lv.1 = 6%
Mutation Lv.2 及以上 = 12%

phase_scale = 0.35 + 0.12 × 当前物种阶段
band        = 1.80（突变可购阶段 0–3）/ 2.00（4–7）/ 2.50（8+）
growth      = 1.45 ^ 该物种“下一个物种（最小 ID 子物种）的前置中已拥有”的数量
              （只数下一步；侧支门票不再把主线价格越拖越贵。没有子物种时 growth = 1）
late_scale  = 1.0，但光合 / 化能在阶段 ≥ 2 购买时取 2.0
first_scale = 0.85（该物种尚未拥有任何突变时），否则 1.0

final_DNA_cost = ceil(base_cost × 内容折扣 × band × phase_scale × late_scale
                      × (1 - discount) × growth × first_scale)
atp_cost       = 0（可购阶段 < 8）
                 或 ceil(clamp(主谱系 ATP/s × 45, 1e7, 5e8))（阶段 8 起）
```

容量扩张改为纯 ATP 支付，价格取
`max(25 × 当前上限 × 1.08^已购级数, 当前 ATP/s × 5)`；
应急储备价格为 `1000 × 1.6^已购级数`，**级数硬顶 26 级**（v9 P0-20：0.94^26 已触底 0.20，
第 27 级零收益），危机减免在环境侧封顶 −50%。

第十五轮把前期价格抬高：首突变从约 4 DNA 提到约 10 DNA，阶段 0–3 的所有突变统一 ×1.8。
阶段 8 起的高阶突变额外消耗 ATP（阶段 8 约 1,000 万，阶段 13 约 3.3 千亿），
让后期溢出的 ATP 重新变成决策资源。

第十轮起基价随阶段缩放：阶段 0 只付 35%，阶段 5 约 95%，阶段 8 约 131%。
光合作用与化能合成不再有阶段上限，但阶段 2 之后补课价格翻倍，避免“错过阶段 0–1 就永久锁死分支”。

### 6.4 候选生成

1. 排除物种已经拥有的突变。
2. 排除阶段、前置和永久等级不满足的突变。
3. 如果下一阶段仍缺必需突变，候选中强制出现一个缺失的必需突变（不再等待生物量门槛）；该保底突变按原价 `60%` 计价（`KEY_MUTATION_DISCOUNT = 0.40`）。
   “下一阶段”指 `species_main_child()` 给出的主线后继（不是“最小 ID 子物种”，见 §5.4），且只在阶段 ≤ `MAINLINE_GUARANTEE_MAX_PHASE`（12）时保底 —— 最深一层（宇宙织锦，阶段 13）必须自己抽到门票，保底不替玩家兜底。
4. 候选生成后检查可支付性：若全部候选都高于 `当前 DNA + 15 秒 DNA 收入`，用池中最便宜的未选项替换最贵的非保底项，保证至少一张买得起。
4. 剩余位置按权重抽取。普通权重为 100，稀有权重为 20。
5. `Mutation Lv.4` 将稀有权重从 20 提高到 40。
6. 基础候选数为 2，`Mutation Lv.3` 后为 3。
7. 候选生成后写入 `MutationOfferState`。在成功选择、物种分化或新轮开始前不得重新抽取。

随机数使用保存于 `RunState` 的 `rng_state`。建议使用 `xorshift32`，不使用全局 `rand()`，确保读档后不会改变下一次抽取序列。

### 7.3 环境倍率

当前事件取对应特征值作为 `score`。

```text
score >= difficulty + 1  → raw multiplier = 1.25
score == difficulty      → raw multiplier = 1.10
score == difficulty - 1  → raw multiplier = 0.85
score <= difficulty - 2  → raw multiplier = 0.60
```

永久适应效果随后应用。

```text
Adaptation Lv.1 且倍率小于 1
multiplier = 1 - (1 - raw_multiplier) × 0.92

Adaptation Lv.4 且倍率大于 1
multiplier = 1 + (raw_multiplier - 1) × 1.15
```

`Adaptation Lv.2` 使危机持续时间乘以 `0.85`。`Lv.3` 在事件开始前 20 秒显示下一事件。`Lv.5` 每轮提供一次保护。当主谱系预计跌到危机开始时种群的 20% 以下时自动触发，把本次固定步及后续该危机的种群损失降低 80%，并同时设置 `adaptation_shield_used = true` 和 `adaptation_shield_active = true`。当前危机结束时清除 `adaptation_shield_active`，不清除本轮的 `adaptation_shield_used`。

## 8. 产率与种群公式

### 8.1 物种规模

```text
population_scale = population / 10
dna_population_scale = population_scale ^ 0.25
```

种群为 10 时产生物种表中的基础每秒产率。DNA 使用 `dna_population_scale`，ATP 与 Biomass 仍使用线性的 `population_scale`。

### 8.2 永久生产倍率

```text
ATP permanent multiplier =
    (Metabolism Lv.1 ? 1.08 : 1.00)
  × (Metabolism Lv.4 ? 1.12 : 1.00)

Biomass permanent multiplier =
    (Metabolism Lv.2 ? 1.08 : 1.00)
  × (Metabolism Lv.4 ? 1.12 : 1.00)

DNA permanent multiplier =
    (Metabolism Lv.4 ? 1.12 : 1.00)
```

Metabolism Lv.3 使新轮以 50 ATP 开始，并免费获得 1 级 Metabolism 单轮升级。

### 8.3 资源产率

每个物种分别计算。

```text
ATP/s = base_ATP
      × population_scale
      × run_metabolism_multiplier
      × mutation_ATP_multiplier
      × environment_multiplier
      × permanent_ATP_multiplier
      × synergy_multiplier

Biomass/s = base_Biomass
          × population_scale
          × run_reproduction_multiplier
          × mutation_Biomass_multiplier
          × environment_multiplier
          × permanent_Biomass_multiplier
          × synergy_multiplier

DNA/s = base_DNA
      × dna_population_scale
      × run_genome_multiplier
      × mutation_DNA_multiplier
      × environment_multiplier
      × permanent_DNA_multiplier
      × synergy_multiplier

Knowledge/s = base_knowledge
            × population_scale ^ 0.5
            × run_genome_multiplier
            × environment_multiplier
            × permanent_production_multiplier
            × synergy_multiplier
```

多个突变的同类百分比先相加。例如 ATP +25% 与 ATP +30% 得到 `mutation_ATP_multiplier = 1.55`。

`base_knowledge` 为 0 的物种（阶段 0–5）不产出理念。
DNA/s 在阶段 0–1 额外乘以 `1.5`（`EARLY_DNA_BONUS`），用于缓解开局饥饿。
上述四项产率在乘以子升级乘数、洞见倍率与随机增益倍率后才是最终值，见 §8.8、§8.9。

### 8.4 最终种群上限

```text
cap = base_cap
    × (1 + mutation_cap_bonus_sum)
    × (Diversification Lv.1 ? 1.10 : 1.00)
```

### 8.5 种群变化

正向增长使用简化的容量限制模型。

```text
positive_growth = population
                × base_growth
                × run_reproduction_multiplier
                × mutation_growth_multiplier
                × (1 - population / cap)

event_loss = population
           × event_damage_per_second
           × (2 - environment_multiplier)
           × (1 + 0.25 × stage)
           × 2.0                       (CRISIS_DAMAGE_MULTIPLIER)
           × (1 - 基石减伤)
           × (1 - Adaptation 减伤)
           × (1 - 0.10 × 应急储备等级)

population_delta_per_second = positive_growth - event_loss
```

危机事件期间，被压制一方（`environment_multiplier < 1`）的产率再乘以 `0.40`；适应良好的一方不受额外惩罚。

当 `population >= cap` 时，`positive_growth` 取 0。写回后每个活跃物种最少保留 `1.0` 种群，最高不超过最终上限。

Meteor Impact 的即时损失为 `min(0.35 + 0.05 × stage, 0.45)`，再乘以应急储备减免，只在事件开始的一个固定步应用一次；v8 起事件持续 30 秒内所有谱系四项产率再乘 `0.4`。v7 起，即时损失发生后会把危机起始人口与最低人口一起重置为损失后的人口，判定语义为“挨完这一下之后还能不能守住”，避免阶段 ≥6 时数学上不可通。普通事件不产生即时损失。

### 8.6 危机通过

事件开始时记录主谱系种群；事件期间逐帧记录主谱系最低人口 `crisis_min_population`。事件结束时满足以下条件即计为度过危机。

```text
crisis_min_population >= max(1, starting_main_population × era_pass_ratio)
era_pass_ratio = 0.672（纪元 1）/ 0.70（纪元 2）/ 0.75（纪元 3）
```

第十一轮起判定口径由“结束瞬间人口”改为“事件期间最低人口”，并把通过线下调到 70%：人口在事件中靠复利涨回来不再能蒙混过关。

**v9 P0-19 的两处重定标**（都要求复跑 1000 种子后再动）：

- `era_pass_ratio` 改为 `0.672 / 0.70 / 0.75`。0.85 的纪元 3 会把单局危机次数推到 7 次以上，
  全清率压在 3% 以下；0.75 后回到 30% 带，同时仍是三档里最严的一条线。
  纪元 1 这条线对数值极敏感（0.672 → 全清 37%，0.675 → 6%），因为单局危机损失集中在 33% 附近。
- 危机伤害的阶段放大从 `1.0 + 0.25 × stage` 改为 `CRISIS_EARLY_SCALE + 0.25 × stage`
  （`CRISIS_EARLY_SCALE = 0.80`）。每个纪元第一次危机落在 60 s、主谱系还在阶段 1–2，
  旧公式下没有对应适应性状就等于必死，纪元 2 的微光期首次通过率只有 0.3%。

同一环境 ID 在一轮只记一次。Normal Ocean 不计危机。

**Meteor Impact（v8）**：一次性人口损失 `min(0.35 + 0.05×阶段, 0.45)`，
且判定基准仍为“损失后人口”；事件持续 30 秒，期间所有谱系四项产率再乘 `0.4`
（`METEOR_PRODUCTION_SCALE`）。威慑从“一次性抽签”改为“少赚 30 秒的钱”。

### 8.7 单轮资源出口

- **容量扩张**：每次使最终种群上限 `+5%`，无等级上限。价格按“未含容量加成的上限”计，
  避免已买容量把下一级再推高一次：

  ```text
  cap_without_capacity = final_population_cap / (1 + 0.05 × capacity_levels)
  cost = max(0.5 × cap_without_capacity × 1.08^capacity_levels,
             atp_per_second × 5)
  ```

  支付为纯 ATP。查询拆价用 `evolution_capacity_atp_cost` 与
  `evolution_capacity_biomass_cost`，提交仍只走 `evolution_apply_capacity_upgrade`。
- **应急储备**：`cost = 1000 × 1.6^已购次数`，减伤系数为
  `max(0.20, 0.94^已购次数)`。**v9 P0-20：硬顶 `RESERVE_MAX_LEVEL = 26`** ——
  0.94^26 ≈ 0.20 已触底，第 27 级只花钱不加防御，属于“零收益高价”，
  因此不再出售；查询与购买两侧共用同一个上限。

两者都属于单轮状态，进入存档，不跨轮保存。

### 8.8 理念、子升级与洞见

理念是第九轮加入的第 4 资源，出口是子升级与洞见。

```text
sub_upgrade_cost(tier) = base_knowledge_cost × 3.2^tier
sub_upgrade_multiplier  = ∏ 已购层级的 multiplier

insight_cost(level)  = 2000 × 1.9^level
insight_multiplier   = 1.02^level
```

- 阶段 ≥ 6 的 10 个物种各有 3 层命名升级，共 30 层。
- 层级必须按 `tier` 顺序购买；已购层数保存在 `RunState.tech_levels[species_id]`。
- 每层乘数统一为 `×1.35`，单物种三层合计 `×2.46`。
- 子升级乘数乘算该物种的 ATP / Biomass / DNA / 理念四项产率。
- 层级绑定物种编号而不是物种槽：谱系分化后旧物种的未购层级不能再买，也不再影响新物种。
- **洞见**是无上限的知识出口：每级使全部物种的四项产率再乘 `1.02`，价格逐级 `×1.9`。
  它用来吸收后期溢出的理念，与子升级同时生效（两者相乘）。
- 子升级与洞见都属于单轮状态，进入存档，不跨轮保存；理念本身不计入 EP。

### 8.9 随机增益因子

页面上会随机刷新一个四处飘动的因子（细胞 / 发光 DNA / 囊泡 / 孢子四种外观），
点击后获得限时增益或一次性资源包。因子与增益状态保存在 `RunState`：

| 字段 | 含义 |
| --- | --- |
| `buff_visible` / `buff_visible_type` / `buff_visible_icon` | 当前页面因子是否存在、类型与外观 |
| `buff_spawn_timer` | 距下次刷新的秒数 |
| `buff_active_type` / `buff_active_time_left` | 生效中的限时增益与剩余秒数 |
| `buff_clock` / `buff_last_rare_time` | 本纪增益计时与上次强增益时点 |
| `buff_total_active_time` / `buff_collected` / `buff_rare_collected` | 统计量 |

```text
刷新间隔 = 45 + rand(0,1) × 45      （45–90 s，最多同时 1 个）
类型权重：普通产率 40 / 点击 25 / 资源包 25 / 强增益 10
普通产率：四项资源 ×1.2，30 s
强增益：  四项资源 ×1.5，15 s；需要 ≥90 s 冷却，开局 90 s 内不出现
点击增益：点击收益 ×2，30 s（不放大自动产率）
资源包：  立即获得 5 s ATP + 30 s Biomass + 15 s DNA + 15 s 理念
```

- 新出现的限时增益覆盖旧增益，不叠乘；资源包不产生限时状态。
- 刷新与类型抽签都使用 `run.rng_state`，同一随机种子下序列完全可复现。
- 增益倍率只作用于四项资源产率与点击，不改变种群上限与危机伤害。

### 8.10 纪元阶段封顶

v8 给每个纪元一个阶段深度上限，到顶后只能横向扩展（买突变、发现同阶段物种）：

```text
era_stage_cap = 8（纪元 1）/ 10（纪元 2）/ 13（纪元 3）
```

- `evolution_era_stage_cap(game)` 返回当前上限，供 UI 显示。
- `evolution_validate_speciation` 拒绝 `species_phase(target) > cap` 的分化，
  返回 `ACTION_REQUIREMENT_NOT_MET`。
- 同阶段或更低阶段的分化仍然允许，因此三槽可以各走一条并行支线。
- 该限制只影响分化，不限制突变购买、容量或储备。
- 演示回归另记 `RAMPTIME`：本纪元主谱系首次达到 `era_stage_cap` 的耗时（-1 = 没到顶）。
  它跨纪元可比；实测纪元 1 到顶（阶段 8）中位 428.8 s、纪元 3 到顶（阶段 13）
  只有 5.1% 的局做到、其中位 425.4 s —— 说明跨轮物资省下的是“重新起步”，
  不是“爬坡本身”。

### 8.11 演示回归的台账口径（v9 P2）

`demo/demo_b.c` 的批量回归输出四组台账，验收脚本直接读它们：

| 台账行 | 字段 | 口径 |
| --- | --- | --- |
| `ATPSUM,局,纪元,支出,结余,残差` | 6 列（含标签） | 支出只认实际扣款（`before - after`）；残差 = 期初 + 收入 − 支出 − 期末，**必须为 0**，验收上限 1 ATP |
| `RAMPTIME,局,纪元,到顶耗时,首分化即时` | 5 列（含标签） | 到顶耗时见 §8.10；末列 1 表示首次分化落在纪元第一步 |
| `BATCH2/BATCH3` | 固定列 | EP、阶段、突变、物种、危机、Biomass、首次分化/突变时点 |
| `CRISIS` | 10 列 | 逐次危机的起始人口、最低人口、通过线、是否通过 |

`atp_spent` 以前在桩内累加本地算出的 `cost`，改价后会和钱包静默错位；
现在四处出口（升级、突变、储备、容量）统一记 `before - after`，
并用“期初 + 收入 − 支出 = 期末”闭合校验。收入侧在产出、点击、瞬时增益三处累加，
环境步不改 ATP，所以闭合残差应当恒为 0（v9 实测最大 0.004 ATP，为浮点尾数）。

**`first_speciation` 在纪元 3 不再有信息量**：跨轮物资足以在第一步买下光合并完成分化，
89.8% 的局记成 0.1 s（时钟分辨率下限）。这条指标只用于纪元 1（首分化 p50 165.9 s），
纪元 3 的爬坡看 `RAMPTIME` / 阶段分布，不要拿 0.1 s 当“变快了”。

### 9.2 统计口径

- `E` 为本轮主谱系抵达的最高阶段，不含阶段 0。
- `M` 为本轮首次获得的不同突变数。
- `S` 为本轮首次发现的不同非初始物种数，原始细胞不计。
- `C` 为本轮首次成功度过的不同危机数，最多取 6。
- `B` 为最高 Biomass 里程碑等级。

```text
EP = 2E + floor(M / 3) + floor(S / 2) + min(C, 6) + B
```

当前内容（阶段 13、204 个突变、185 个非初始物种）的理论上限为
`2×13 + 68 + 92 + 6 + 10 = 202`。

预览与正式结算必须调用同一个函数。确认结束后先设置 `reward_claimed` 并切换到 Legacy 阶段，再把 EP 余额和整个状态写入存档，不能存在只完成一半的状态。

## 11. 随机数规则

所有玩法随机数都来自 `RunState.rng_state`，用于突变候选和环境事件。

```c
static unsigned int next_random(unsigned int *state)
{
    unsigned int value = *state;
    value ^= value << 13;
    value ^= value >> 17;
    value ^= value << 5;
    *state = value;
    return value;
}
```

新游戏使用非零时间值初始化。读档后继续使用存档中的状态。测试可以使用固定种子，确保结果可复现。

## 12. 存档格式

课程版采用带版本头的二进制存档，目标是在同一 Windows 项目和同一编译器下恢复游戏。

```text
8 bytes  magic        "TOLSV001"
4 bytes  version      8
4 bytes  payload_size sizeof(GameState)
N bytes  payload      GameState
```

`version` 当前为 8：在版本 7 之上，统一 A/B/C 存档加入了成长成就位
`achievement_flags`，并把容量/储备动作编号追加到 `ActionType` 末尾。
`RunState` 的随机增益因子状态（`buff_visible` / `buff_spawn_timer` / `buff_active_*` /
`buff_clock` / 统计量）与无上限洞见等级 `insight_levels` 一并写入载荷。magic 暂保持
`TOLSV001` 不变；若后续改为带 CRC 的头部，应整体升级为 `TOLSV008` 并同步 A 的 `save.c`。

读取时依次检查 magic、version、payload size、阶段枚举、数组数量、ID 范围和所有资源非负值。任何检查失败都保留当前状态并返回错误。

保存时先写 `save.tmp`。写入和关闭成功后再替换正式存档，避免程序中断产生半份文件。课程版不承诺不同编译器之间共享旧存档。结构变化时提高 `version`。

## 13. 第一轮验收脚本

三个成员完成首次集成后，用同一个固定随机种子执行以下流程。

1. 原始细胞点击并购买一次 Metabolism。
2. 等待产生 DNA，生成突变候选，关闭再打开后候选保持不变。
3. 获得 Photosynthesis 或 Chemosynthesis，分化为对应阶段 1 物种。
4. 经历至少两个环境事件，确认不同特征产生不同倍率和种群结果。
5. 打开 End of Era，记下逐项 EP，取消后继续游戏，数据保持不变。
6. 再次打开并确认结束，EP 只增加一次。
7. 购买一项永久强化，保存并重新启动。
8. 新轮确认该强化生效，旧轮资源和突变已经重置，图鉴仍保留。
9. 修改存档阶段为 Legacy 后再次读取，确认不能重复领取旧奖励。
10. 使用含 Diversification Lv.2 和 Lv.3 的测试存档，确认第二物种槽与 10% 协同生效。

以上十步全部通过，才算玩法闭环可以进入 UI 优化和内容扩充。
